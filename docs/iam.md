# 用户、角色与菜单权限契约

## 模型与关系

用户沿用 `lambo_accounts`，保留密码摘要和会话；`SystemUser` 为管理接口的安全投影。角色和菜单分别维护启停，用户通过 `AccountRole` 关联多个角色，角色通过 `RoleMenu` 关联目录、页面和按钮。多角色权限取并集；菜单及其祖先必须启用，按钮依附页面，页面组件限制在已注册的业务组件内。数据库保存授权分配，接口权限码常量仅定义资源所需权限。

## 动作与不变式

- 用户：分页筛选、新增、详情、编辑、启停、删除、分配角色、重置密码。新密码 12—72 字节；密码不回显，不使用普通编辑修改密码。
- 角色：分页筛选、增删改查、启停及菜单权限树授权。分配只能引用已存在记录，拒绝重复编码，删除已分配角色前须解除关联。
- 菜单：树形展示、筛选、增删改查、启停及排序；拒绝循环、非法父类型、路由冲突和未知组件/接口权限码。删除有子节点或已授权的菜单前须解除关联。
- 写操作在事务中串行校验，防止并发删除最后一个有效管理账号。必须保留至少一个拥有完整用户、角色、菜单管理权限且可访问管理页面的启用账号。
- 管理者只能分配或修改自身拥有的权限范围，不能通过修改角色或菜单实现提权。
- 角色授权、成员关系或菜单权限变化后撤销受影响会话；重新登录加载新的菜单和按钮。账号停用、删除及密码重置撤销该账号全部会话。
- 旧单角色字段仅用于一次性兼容迁移；迁移后以关系表为准，不因启动而重新授予已撤销权限。

## 生成与扩展

输入为 `tools/lambo/examples/system-{user,role,menu}.json`。依次执行 `lambo create all <名称> --schema <文件>`，得到三个模块共 30 个前后端基线文件（每模块后端 4 + 前端 5 + 菜单脚本 1）。基础字段、校验、列表、详情、表单及 HTTP 契约复用生成结果；多对多关系、授权树、密码动作、树形菜单和鉴权在基线上扩展。初始产物副本保存于本地 `.artifacts/iam/generated/`，业务扩展后再次生成应报告差异，不覆盖修改。

## 初始化数据

稳定数据放在 `backend/internal/system/repository/seed/iam.sql`，由 `InitializeIAM` 在首次启动时嵌入执行，整体包在一个事务里并持有 advisory lock，只跑一次（`rbac-v1` 标记），不会在后续启动恢复人工撤销的授权。

脚本只写角色和菜单骨架（目录、页面），使用固定 ID 建立父子关系。按钮不写进 SQL，由页面权限前缀从 `PermissionCatalog` 派生成，避免菜单与权限码两处维护；管理员密码依赖运行时哈希，也不进 SQL。只读角色默认获得不挂在系统管理下的业务页面查询权限，系统管理页面不授予。

`TestSeedSQLSplitsStatementsAndMatchesPermissionCatalog` 检查脚本可被正确拆分，且其中的页面权限码都存在于权限目录。新增系统模块时需要同步更新这份 SQL 与 `PermissionCatalog`。

业务模块不走上面的一次性脚本。`lambo create frontend <名称>` 会在 `backend/internal/<domain>/seed/<名称>.sql` 生成幂等菜单脚本（page + 三个 button + admin 授权），由 `lambo db seed <名称>` 显式执行，不在启动时自动运行，避免重启改写人工调整过的授权。未执行时该模块接口按权限码返回 403、前端按钮隐藏：`account.Codes` 只从已授权且启用、父链完整的菜单 `permission` 聚合，代码中声明常量不等于已下发。

## 验收

页面创建菜单、角色、用户，分配多个角色并登录核对菜单/按钮；新增与修改授权后重新登录验证生效；直接调用未授权接口返回 403。覆盖密码重置、停用、撤权、删除约束、最后一个管理员保护和多角色合并，完成构建、类型检查与真实 PostgreSQL 联调。部门、岗位、数据范围及生产部署不在本轮范围。
